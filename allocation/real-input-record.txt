Real-window input check for the allocation screen (RealInput.cs)

Host: Windows 11 Pro 10.0.26200, display scaling 125% (120 DPI), Per-Monitor V2 aware harness.
Input: OS-injected with SetCursorPos / mouse_event / keybd_event into a topmost 1070x630 window
showing ResizeDisk with C: 476 GiB (168 GiB free, 120 GiB shrinkable) and D: on a second disk.
offset = measured Thumb centre minus the right edge of the rendered Windows column, in DIP,
both in page coordinates.

Caveat: these runs started the window with Application.Run, which also ran Libertix's real
App.OnStartup in the harness process and showed its permission prompt. The prompt was left
unanswered and nothing was written under C:\LibertixInstallLogs. When the harness was changed
not to raise Startup, its window could no longer take the foreground, so no further input was
sent (the harness now refuses to send input unless its own window is in front).
